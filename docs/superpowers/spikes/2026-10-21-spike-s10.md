- Date : 2026-10-21. Claude Code 2.1.305 au premier lancement (mise à jour automatique en 2.1.306 pendant le spike ; les lancements suivants sont en 2.1.306), modèle `claude-opus-5-5`, tmux 3.5a (WSL2).
- Accord de l'auteur obtenu pour lancer le vrai `claude` (`HOME` réel, authentification existante). Serveur tmux jetable `-L meute-spike-s10 -f /dev/null`, tué à la fin (`kill-server`) ; dossier jetable approuvé, `…/scratchpad/s10` ; `~/.claude/settings.json` et `~/.claude.json` non modifiés ; réglages passés uniquement par `--settings`.
- Échange minimal : un message (`say ok. remember the word PINEAPPLE`), puis une question de rappel.
- Premier lancement : Claude a affiché l'invite « Is this a project you created or one you trust? » pour le dossier jetable ; réponse « Yes, I trust this folder » (`Up`, `Enter`).

## Synthèse

| Question | Réponse |
|---|---|
| 1. `SessionStart` sur `--resume` | Oui. `source` = **`resume`**, `session_id` = **le même uuid** |
| 2. `MEUTE_SESSION` dans le hook | Oui, valeur identique (au démarrage et à la reprise) |
| 3. Options ensemble | `--settings`, `--resume <uuid>`, `--permission-mode manual`, `--name=s10` acceptées. `--session-id` avec `--resume` est **rejeté** |
| 4. Conversation reprise | Oui : le message d'origine est affiché et Claude répond `PINEAPPLE` |
| 5. `respawn-pane -k` | Oui, sur un panneau mort (`remain-on-exit on`) ; **même `pane_id`** |

## Mise en place

`hook.sh` copie stdin dans `out/hook-<ns>.json` et écrit `MEUTE_SESSION=${MEUTE_SESSION-<unset>}` dans `out/env-<ns>.txt` ; `settings.json` ne déclare que `SessionStart`, sans `matcher` :

```json
{"hooks":{"SessionStart":[{"hooks":[{"type":"command","command":"<dossier>/hook.sh"}]}]}}
```

uuid de la session : `46332ea7-40c0-49ae-b8a4-4deb3f3335a0`.

## Commandes

```bash
T="tmux -L meute-spike-s10"
$T -f /dev/null new-session -d -s s10 -x 120 -y 40 -c "$S" bash
$T set-option -g remain-on-exit on

# 1. Premier lancement (dans le panneau %0)
MEUTE_SESSION=$U claude --settings $S/settings.json --session-id $U \
    --permission-mode manual --name=s10

# 2. Reprise dans une nouvelle fenêtre, la commande est celle du panneau
$T new-window -d -n w2 -c "$S" -e MEUTE_SESSION=$U \
    "claude --settings $S/settings.json --resume $U --permission-mode manual --name=s10"

# 3. Panneau mort -> respawn
$T respawn-pane -k -t %1 -e MEUTE_SESSION=$U \
    "claude --settings $S/settings.json --resume $U --permission-mode manual --name=s10"
```

Sorties : `claude` quitte avec `C-c` deux fois **à moins d'une seconde d'intervalle** (à 1 s d'intervalle, le premier panneau est resté ouvert).

## 1. Le hook arrive-t-il à la reprise ?

Premier lancement (`source` `startup`) puis reprise : le hook arrive, avec le même `session_id`.

Écarts entre les deux : à la reprise, `source` vaut `resume`, il n'y a **pas de `model`**, et quatre champs apparaissent (`seconds_since_last_response`, `context_tokens`, `prompt_cache_likely_expired`, `estimated_cache_write_usd`). `transcript_path` est le même fichier (la reprise n'en crée pas un autre). Deux reprises (fenêtre `w2`, puis `respawn-pane`) : toutes `source: resume`, même `session_id`. Aucun `rebinds` n'a été nécessaire.

## 2. `MEUTE_SESSION`

Les trois fichiers `env-*.txt` (un `startup`, deux `resume`) contiennent la même ligne : `MEUTE_SESSION=46332ea7-40c0-49ae-b8a4-4deb3f3335a0`. La variable passe par `-e` de `new-window`/`respawn-pane` comme par un préfixe de shell.

## 3. Options ensemble

`--settings <fichier> --resume <uuid> --permission-mode manual --name=s10` : lancée sans erreur, bandeau « manual mode on ». Avec `--session-id <uuid>` en plus :

```
Error: --session-id can only be used with --continue or --resume if --fork-session is also specified.
```

(code de sortie 1 ; dans tmux, le panneau meurt aussitôt avec `pane_dead_status=1`). Pas de `--session-id` avec `--resume`, donc.

## 4. Conversation reprise

L'écran montre `❯ say ok. remember the word PINEAPPLE` et la réponse d'origine ; à la question « what word did I ask you to remember? one word », Claude répond `PINEAPPLE`.

## 5. `respawn-pane -k` sur un panneau mort

Avec `remain-on-exit on`, après sortie de `claude` : `%1 w2 dead=1 status=0`. `respawn-pane -k -t %1 …` (code 0) relance : `%1 w2 dead=0 cmd=claude`, **même `pane_id` `%1`**, l'historique s'affiche, un `SessionStart` `source: resume` arrive. Réserve : le panneau mort testé venait d'un lancement `--resume`, pas `--session-id` (le premier panneau lancé avec `--session-id` tournait sous `bash`, donc ne mourait pas) ; `respawn-pane` ne dépend pas de l'argv précédent.

## Décision pour le Task 3

- Forme exacte de la reprise (jamais de `--session-id` avec `--resume`) :

  ```
  claude --settings <fichier> --resume <native_id> --permission-mode <mode> --name=<titre>
  ```

  dans l'environnement `MEUTE_SESSION=<id meute>`.
- Panneau mort : `tmux respawn-pane -k -t <pane_id> -e MEUTE_SESSION=<id> <argv>` ; le `pane_id` est conservé, rien à re-enregistrer.
- `SessionStart` attendu : `source: "resume"`, avec le **même** `session_id` que le `native_id` enregistré. Ne pas compter sur `model` (absent à la reprise).
- `rebinds` : pas nécessaire pour ce cas observé. Garder tout de même la tolérance (un `native_id` nouveau reste accepté) : le `--fork-session` ou une session ancienne non reprenable pourrait en produire un, ce qui n'a pas été essayé.
- Mise à jour du comportement `claude_argv` : ajouter une variante `resume` sans `--session-id`.
