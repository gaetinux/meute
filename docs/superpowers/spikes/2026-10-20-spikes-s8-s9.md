## S9 — démarrage de la saisie rapide dans `tmux display-popup`

### Méthode

Script jetable (hors dépôt) : importe `meute.cli.context` et `textual.widgets`, ouvre la base (`open_context`, `XDG_*` pointant vers un dossier temporaire), lance une application Textual avec un `Input` qui se ferme au premier rendu (`call_after_refresh`). Avec `S9_STAMP`, il écrit `time.time()` à ce premier rendu.

```bash
# processus seul (interpréteur du venv, puis via `uv run`)
hyperfine --warmup 3 -r 20 ".venv/bin/python s9.py"
hyperfine --warmup 3 -r 20 "uv run --project <dépôt> python s9.py"

# popup : serveur jetable + client attaché, mesure de `display-popup -E` jusqu'au premier rendu
tmux -L meute-spike-s9 -f /dev/null new-session -d -x 160 -y 45 -s s9
script -qfc "tmux -L meute-spike-s9 attach" /dev/null &
t0=$(date +%s.%N); tmux -L meute-spike-s9 display-popup -E -w 60 -h 5 "env S9_STAMP=… python s9.py"
tmux -L meute-spike-s9 kill-server
```

### Mesures

| Mesure | Résultat |
|---|---|
| Processus seul, venv direct (démarrage + rendu + sortie), 20 exécutions | 337,3 ms en moyenne (σ 2,8 ms ; 333,8 à 342,5) |
| Idem via `uv run` | 350,9 ms (σ 5,2 ms) |
| Popup : de `display-popup -E` au premier rendu, 10 exécutions | 204 à 216 ms (médiane environ 207 ms) |
| Popup : de `display-popup -E` à la fermeture de la popup | 406 à 426 ms (inclut l'arrêt de Textual et le nettoyage) |

### Décision

Le champ est utilisable environ 210 ms après le raccourci, sous le seuil de 400 ms : **S9 est réussi**, la saisie rapide en popup (Task 12) est retenue, le repli « saisie dans le tableau » n'est pas nécessaire. Le point d'entrée réel (`meute`, avec `typer` paresseux) ajoute peu au script mesuré, la marge est d'environ 190 ms. Le serveur `meute-spike-s9` est tué à la fin.

## S8 — collage entre crochets (`paste-buffer -p`) dans le vrai Claude

L'auteur a donné son accord explicite pour lancer le vrai `claude`, dans ce cadre seulement : serveur jetable `meute-spike-s8`, `HOME` réel (authentification), dossier déjà approuvé, `--settings` ne définissant qu'un hook `SessionStart` (`date +%s.%N >> fichier`). Aucune touche d'envoi n'a été émise : seulement `load-buffer`, `paste-buffer -p -d`, `capture-pane`. Aucun fichier de configuration de l'utilisateur modifié.

### Forme des retours à la ligne

Texte collé (fichier `0600`, 29 octets) : `#12 Title\n\nLine one\nLine two;`. Fenêtre jetable avec `stty raw -echo; printf '\e[?2004h'; head -c 40 | od -c`, puis `tmux load-buffer -b s8 fichier` et `tmux paste-buffer -p -d -b s8` :

```
ESC [ 2 0 0 ~ # 1 2 ␠ T i t l e \r \r L i n e ␠ o n e \r L i n e ␠ t w o ; ESC [ 2 0 1 ~
```

Les retours à la ligne arrivent en **`\r`** (tmux remplace `\n` par `\r` sauf avec `-r`), encadrés par `ESC[200~` / `ESC[201~`. Le `;` final est conservé (le passage par fichier évite la coupure tmux d'un argument finissant par `;`).

### Délai après `SessionStart`

Un démarrage de `claude` par essai (4 démarrages au total, dont un essai invalide : le nom de fenêtre `c0.5` contenant un point n'était pas adressable par `-t`, refait sous le nom `c05`). Le collage est lancé N secondes après l'écriture de l'horodatage du hook.

| Collage après `SessionStart` | Résultat (capture après 1,5 s) |
|---|---|
| +0,009 s | Texte entier dans la saisie (`❯ #12 Title`, ligne vide, `Line one`, `Line two;`), non envoyé |
| +0,531 s | `❯ [Pasted text #1 +3 lines]`, non envoyé |
| +1,032 s | `❯ [Pasted text #1 +3 lines]`, non envoyé |

À chaque essai, le texte est dans la saisie, non envoyé (rien n'est parti : pas de réponse de Claude). Dès le premier essai, à 9 ms du hook, le collage est accepté comme collage entre crochets (le texte n'a pas été interprété comme des frappes : sinon le `\r` aurait envoyé la saisie). Selon l'instant, Claude affiche le texte entier ou le résumé `[Pasted text #1 +3 lines]` ; le contenu envoyé à l'Entrée est le même texte entier.

Limite : un seul essai par délai (au plus 4 démarrages autorisés) ; le délai minimal réel est donc inférieur ou égal à 0 s, sans mesure plus fine.

### Décision

- `PASTE_DELAY_SECONDS = 0.5` : le collage est déjà accepté à +0,01 s ; 0,5 s laisse une marge sur une machine plus lente ou chargée sans retard sensible. (Le défaut de repli de 1 s du brief reste correct si l'on préfère être prudent.)
- Forme des retours à la ligne dans le collage : `\r`. Le code de Task 13 ne doit pas convertir ni compter sur `\n`.
- Nettoyage : `tmux -L meute-spike-s8 kill-server` ; aucun `claude` démarré par le spike ne subsiste (les autres processus `claude` de l'utilisateur n'ont pas été touchés).
