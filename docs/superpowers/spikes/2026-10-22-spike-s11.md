## Mise en place

Serveur jetable `srv.py` (`mcp` 2.x : `FastMCP` a été renommé `MCPServer`, `from mcp.server.fastmcp import FastMCP` échoue avec `ModuleNotFoundError`, d'où un premier lancement où `/mcp` affichait `✘ meute`) :

```python
import os, time
time.sleep(float(os.environ.get("S11_DELAY", "0")))
from mcp.server.mcpserver import MCPServer
m = MCPServer("meute")

@m.tool()
def echo_env() -> str:
    """Return MEUTE_SESSION."""
    return "MEUTE_SESSION=" + os.environ.get("MEUTE_SESSION", "<unset>")

@m.tool()
def task_read(task_id: str) -> str:
    """Dummy task read."""
    return "task " + task_id + ": dummy"

m.run()   # stdio
```

(plus une ligne qui écrit l'heure de démarrage et `MEUTE_SESSION` dans `srv.log`). `mcp.json` :

```json
{"mcpServers":{"meute":{"command":"uv","args":["run","--with","mcp","python","<s11>/srv.py"],"env":{"S11_LOG":"<s11>/srv.log"}}}}
```

`settings.json` : `{"permissions":{"allow":["mcp__meute__echo_env","mcp__meute__task_read"]}}`. Le nom d'outil est `mcp__<serveur>__<outil>` (serveur `meute`).

## Commandes

```bash
T="tmux -L meute-spike-s11"
$T -f /dev/null new-session -d -s s11 -x 140 -y 50 -c "$S" bash
$T set-option -g remain-on-exit on

# lancement type (dans le panneau, saisi par send-keys)
MEUTE_SESSION=$U claude --settings $S/settings.json --mcp-config $S/mcp.json \
    --session-id $U --permission-mode manual --name=s11 \
    --append-system-prompt 'Always begin your first reply with the word PINEAPPLE.'
```

Pilotage : texte et `Enter` doivent être envoyés par deux `send-keys` séparés (le texte suivi de `Enter` dans le même appel n'est pas soumis de façon fiable). Sortie : `C-c C-c` dans le même `send-keys`, donc à moins d'une seconde.

## 1. Outils listés

`/mcp` : `✔ meute   2 tools`, en plus de `claude.ai Claude Docs`, `claude.ai Spotify`, `plugin:context7:context7` (`needs authentication`) et `plugin:github:github` (`✘`). La configuration `--mcp-config` **s'ajoute** aux serveurs de l'utilisateur. `--strict-mcp-config` (« Only use MCP servers from --mcp-config ») permettrait de les ignorer ; non essayé.

## 2. Autorisation des appels

Avec `permissions.allow` des deux outils : demande « call the tools echo_env and task_read … » ; Claude répond `Called meute 2 times`, sans boîte de dialogue.

Contrôle : réglages ne contenant que `mcp__meute__task_read`. `task_read` passe, mais `echo_env` affiche :

```
Tool use
 meute — Echo Env Tool: (MCP)
Do you want to proceed?
 ❯ 1. Yes   2. Yes, and don't ask again for meute — Echo Env commands in …   3. No
```

Fusion : `--settings` n'autorisant que `mcp__meute__task_read` et un `.claude/settings.json` de projet (dossier jetable) n'autorisant que `mcp__meute__echo_env` : les deux appels passent sans demande. `permissions.allow` de `--settings` est donc **fusionné** avec celui des autres sources, pas remplacé. (Les réglages utilisateur du poste ne contiennent aucune entrée `permissions` ; la fusion avec `~/.claude/settings.json` n'a pas été testée directement, la source projet sert de preuve.)

## 3. `MEUTE_SESSION`

`srv.log` : `start 1792700237.76 MEUTE_SESSION=59523f9e-0f63-4228-9976-3b17cd9bf49d`, valeur égale à celle posée en préfixe du shell (`MEUTE_SESSION=$U claude …`) ; `echo_env` renvoie la même. Le serveur MCP stdio hérite de l'environnement de `claude`. Aucune clé `env` n'est donc nécessaire dans `mcp.json` pour la transmettre.

## 4. Réglages utilisateur

`~/.claude/settings.json` contient `language: "Français"`. Avec `--settings` en plus, toutes les réponses sont en français : les réglages utilisateur restent actifs, `--settings` s'ajoute. Les hooks utilisateur n'ont pas été examinés (S10 a déjà montré que ceux de `--settings` s'exécutent).

## 5. Consigne du prompt système

Premier échange : `● PINEAPPLE — Salut ! …`. Avec les 20 000 caractères : `PINEAPPLE` / `Ok.` / `ZEBRA` ; consigne de début et de fin toutes deux suivies. Avec `--resume` et `--append-system-prompt-file` (consigne `MANGO`), aucun rejet ; l'effet n'est pas concluant (la consigne parlait de « first reply », déjà passée dans la conversation reprise).

## 6. Variante fichier

`claude --help` ne liste que `--append-system-prompt <prompt>` et `--system-prompt <prompt>` ; les formes `--system-prompt[-file]` et `--append-system-prompt[-file]` n'apparaissent que dans le texte de `--restricted`. Essai : `--append-system-prompt-file <fichier>` est accepté et suivi (`PINEAPPLE` / `Ok.` / `ZEBRA`). Elle n'est pas documentée dans l'aide, donc à considérer comme moins stable.

## 7. Taille

Passé en argument unique (`"$(cat fichier)"`) : 20 000 caractères et 100 000 caractères, sans erreur, début et fin de la consigne suivis. Limite théorique d'un argument sous Linux : 131 072 octets (`MAX_ARG_STRLEN`). Pas d'autre limite atteinte.

## 8. Démarrage à froid

- `uv run --with mcp python -c "import mcp"` : 1,8 s, cache chaud. Lancement de `claude` jusqu'au démarrage effectif du serveur : 1,6 s (l'invite est déjà affichée à ce moment-là).
- Serveur ralenti de 8 s (`S11_DELAY=8`) : message envoyé 3 s après le lancement ; il a été traité, Claude a attendu le serveur (démarré à +9,5 s), appelé les deux outils et répondu, `Brewed for 11s`. Claude n'a pas répondu sans les outils.
- Le démarrage vraiment à froid de `uv` (cache vide) n'a pas été mesuré (ne pas vider le cache de l'utilisateur).

## Décision pour la suite du plan

- **Forme de `mcp.json`** : `{"mcpServers":{"meute":{"command":"<exe>","args":[…]}}}` ; nom de serveur `meute`, donc outils `mcp__meute__<outil>`. Pas de clé `env` : `MEUTE_SESSION` est hérité. Option `--mcp-config <fichier>` (accepte aussi du JSON en ligne). Les serveurs de l'utilisateur restent actifs ; ne pas ajouter `--strict-mcp-config` sans décision explicite.
- **`permissions.allow`** : fonctionne via `--settings` et se fusionne avec les autres sources. Mettre `"permissions":{"allow":["mcp__meute__<outil>", …]}` dans le `settings.json` de session, à côté des hooks et du `statusLine`. Sans entrée, l'outil demande l'autorisation.
- **Forme du contexte** (`ContextArg`) : `--append-system-prompt <texte>` en argument, documenté dans `claude --help` et sans limite pratique jusqu'à 100 000 caractères. La variante `--append-system-prompt-file <fichier>` existe et fonctionne, mais n'est pas dans l'aide ; la garder en repli, à ne pas retenir par défaut. Le texte passe tel quel dans l'argv (pas d'interpolation par un shell : tmux reçoit l'argv, la valeur reste une donnée). Compatible avec `--session-id` ; accepté avec `--resume`.
- **Tailles observées** : 20 000 et 100 000 caractères passés et suivis ; plafond Linux d'un argument 131 072 octets. Plafonner le contexte composé bien en dessous (par exemple 20 000 caractères).
- **Démarrage à froid** : serveur démarré 1,6 s après `claude` (cache `uv` chaud) ; Claude **attend** un serveur lent (8 s) avant de traiter le message. Pas besoin d'attente côté meute. Pour un serveur Python de meute, préférer `sys.executable -m …` du venv de meute plutôt que `uv run --with` (coût d'amorçage).
- **Piège pour le serveur MCP du plan** : `mcp` 2.x a renommé `FastMCP` en `MCPServer` (`mcp.server.mcpserver`) ; épingler la version ou utiliser le nouveau nom.
